# Portable exact database expectations

The existing database templates remain byte-identical. The separate input plan binds each template by SHA-256 and lists the semantic events that feed its string and directory caches. An independent test-side replay builds expected bytes before comparison. The comparison still requires exact ordering, counts, source text, diagnostics, status, ordered witness and full filesystem. Runtime paths, physical identity and libc wall-clock fields retain their existing strict, positioned checks.

The configured include path comes from the already verified oracle build profile, corroborated by the existing standalone configuration probe. The two remaining default include directories are independently checked. Any different inventory of actual default paths fails closed; changes to that inventory can also change variable-table activity and are outside these plans. Cache entries use their full nominal raw span, including bytes after the first NUL where present. Equality uses the visible name; successful new allocation includes the full span and its terminator. The bounded cache model checks the single-buffer and no-rehash conditions, computes the actual probe count and occupancy, and formats native rounding controls with a separately compiled public-libc witness.

The same original public-libc witness opens only declared case paths before and after each run and records actual `readdir` order, entry bytes/type, and open directory identity. The plan replays each search prefix through its selected found/missing/EOF outcome, with explicit cache-reset and process/restart boundaries. A hit at the last entry does not count as an observed EOF. Two logical names sharing one cache must name the same independently observed physical directory. No candidate or stock GNU case stdout selects a path, span, count, directory prefix or comparison exemption. Every execution records its prepared full template and raw independent input observations.

The semantic action plans were derived from an external observer build. Its 61 normal observations independently matched stock GNU twice, including full streams, bounds and filesystem. Replay then matched each observed nominal intern span in order and reproduced each original frozen template. That observer remains discovery evidence only; current executable qualification always uses the pinned stock GNU build as the oracle. The new portable driver passed all 61 original-prefix comparisons, search8 on a second actual filesystem whose directory order and prepared template differed in each case, and the separate authenticated alternate-prefix campaign. The alternate prefix passed DB41/numeric6/generic lifecycle6 and another search8 on tmpfs with a matching alternate candidate; the eight stdin lifecycle cases were GNU2-only in that campaign because the alternate candidate did not include the separate stdin patch.

This is a finite Linux test model. It does not claim arbitrary multi-buffer strcache, new default include-directory inventories, changing directory contents outside the selected cache-reset/process epochs, or other locale/configuration profiles.
