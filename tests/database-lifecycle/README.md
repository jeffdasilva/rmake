# Database lifecycle profiles

These fourteen original profiles compare complete GNU Make 4.4.1 protocols:
literal database transcripts, exact status/stderr, ordered native effects and the complete
work/home/tmp filesystem. Only independently bounded, positioned libc clock
fields vary. Every hash-table/cache statistic and every environment-vector
witness byte is literal. Modules compile once per case before identical reset
GNU2/candidate executions. Existing database41 models remain unchanged.
The recorded C-locale/UTC qualifications use explicitly matched main-oracle
include/lib installation roots. Other build configurations require independent
cache-event parameterization; arbitrary counter adjustments are not permitted.

`tools/database_lifecycle.py --group generic` selects six ordinary named-file
controls: one whole-second cached timestamp and four native restart controls
for absent/present MAKELEVEL, live setenv changes and exact environment order,
plus a failed self-exec with a native module.
`--group stdin` selects eight adopted-source controls: normal completion,
early command error, reader error, actual restart, native finalizer and native
reader error, failed self-exec cleanup and private pipe restoration at unlink.
The default selects all fourteen.
Supply `--oracle` and either
`--candidate` or `--oracle-only`, with `--report` and optional exact `--case`.

The source fixes retain genuine events and ownership: raw internal-source
selection interns its filename; a completed stdin source skips remake traversal;
zero nanoseconds omit the decimal suffix; actual restart preserves live
environment order, updates existing counters and appends only absent
MAKE_RESTARTS. Restart uses actual exec through the existing owned environment
boundary and PATH/ENOEXEC search. Manually injected duplicate environment names
remain unqualified.

The two additional failure profiles use a predetermined missing process-entry
path. Relative argv0 spellings containing '/' are prepared before -C changes;
bare names retain PATH lookup. Failed exec emits the exact error, unlinks any
published stdin source, then exits127 without C/native/Guile finalizers. No
crash/hang exception is used. A separate retained GNU2 success control checks
bare-argv0 PATH restart; it receives no extra inventory credit.

`history11.json.gz` retains complete original plans, first raw observations,
incorrect indentation/path predictions, all refinements, frozen negative
controls, the v1/v2 intermediate failures, v3 source closure, runtime patches,
both final eleven-profile reports and development regressions. Each embedded
file and both archive layers have SHA-256 identities. The v1 source snapshot is
explicitly a retrospective reconstruction; it has no at-build closure credit.

Both v3 builds pass the historical eleven profiles. Development additionally passes original
stdin44, database41, numeric6, fenv18, 645 Rust units and strict workspace Clippy.
The preceding combined source fails the original six; preceding database171
fails all generic five. V2 fixed the original six but failed the independent
environment-order control. These are bounded profile results, with no ordinary
ledger, safety-exception, performance or full M3/M6 completion credit.

`reexec-errors.json` adds the two failure profiles without changing the original
eleven-model file. `qualification13.json.gz` retains both final v4 thirteen-case
reports, the full source/input closure, all development regressions and the
complete new discovery history. Both builds pass thirteen profiles; development
again passes original44/database41/numeric6/fenv18, 645 Rust units and strict
Clippy. Six tooling controls reject shared wrong counters, source flags,
environment order, timestamps, cleanup, finalizer effects and error protocol.

The missing-self-exec discovery initially failed in v3: GNU2 exited127 without
finalizers while v3 exited2 and ran the destructor. An initial observer error
lost raw data before report retention and earns zero credit. A fresh complete
run retained one wrong relative-path prediction, then a predetermined-workspace
path refinement qualified GNU2. All of these remain unchanged in the archives.

`pipe-cleanup.json` adds one original inherited-pipe cleanup profile without
changing those thirteen models. The launcher creates a pipe at fixed auth
descriptors and bounds the descriptor table; an original LD_PRELOAD interposer
checks public F_GETFD flags for every live alias of that exact pipe identity at
owned-source unlink. GNU2 reports zero exposed aliases, while v4 reports two.
The narrow v5 adapter restores private descriptors after the diagnostic and
before source unlink/immediate exit. The original fixture compilation failure
is retained with zero qualification credit.

`qualification14.json.gz` retains the full additive evidence, source/input
closure, both fourteen-profile v5 reports and the failing v4 control (13 pass,
one fail). Both v5 builds pass fourteen profiles; development again passes
original44/database41/numeric6/fenv18, 645 Rust units and strict Clippy. Seven
tooling controls verify the protocol and archive identities. Broader arbitrary
interposition, duplicate environment entries and resource/locale profiles remain
separate work; this does not establish full M3/M6 compatibility.

The `advertised-pair-refinement.json` sidecar keeps the sealed pipe model and its expected results unchanged. The replacement observer captures the advertised authentication pair through an original native function and checks both descriptors at unlink for liveness, original pipe identity, and close-on-exec. The separately retained intentional-close control proves that merely observing an unrelated live pipe cannot pass.
