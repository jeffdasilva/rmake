# Database-output compatibility work

`-p` is an open implementation surface. Mainline continues to reject it. The
unmerged development implementation accepts it and now has frozen development
and optimized fourteen-profile passes; that behavior is not mainline enablement
or full compatibility. A
partial dump must not be reported as compatible.

Fourteen original fixtures cover raw variable forms and provenance, precedence,
target and pattern declarations, implicit rules, VPATH, question mode, ordered
recipe effects, fatal reading, optional missing includes, fixed nanosecond
mtimes, built-ins, and variable-table growth. Their original GNU2 research
assertions are retained alongside exact reference transcripts. The full
transcript expectations were obtained from those observations; they are not
represented as predictions written before the reference executions.

The standalone driver is `tools/database_output.py`, with `--oracle`, either
`--candidate` or `--oracle-only`, `--report`, and repeatable exact `--case`.
It resets the same predetermined absolute paths for GNU, GNU, and the candidate.
All streams, exit status, complete filesystem, ordered `seen` effects, repeats,
and child/output/time bounds are mandatory.

Every database byte is literal, including table order, lookup/collision/rehash
counts, string-cache storage and hit rates, version headers, variable origins,
and fixed file timestamps. Only these explicitly positioned fields vary:

- The opening and closing C-locale ctime must each fall within independently
  sampled libc `time(NULL)` bounds, have a valid calendar/weekday/spacing, and
  remain ordered. High-resolution realtime is retained separately; no tolerance
  is added when the Linux coarse/vdso domain crosses a second boundary.
- Each declared directory's device/inode must equal independent `stat` results
  from that predetermined path before and after execution. Renaming or replacing
  that directory fails this finite profile rather than broadening the comparison.

Path substitution uses the reset root chosen before any child runs. The driver
never extracts replacement paths from output. Identity-looking user strings,
extra/moved headers, changed statistics, and shared wrong results remain errors.
There is no help/version branding exception in database protocol output.

The profile is bounded to the pinned Linux/x86-64 GNU Make 4.4.1 C-locale/UTC
configuration. These fixtures give no ordinary-ledger or safety-exception credit.
The strict GNU2 gate passes all fourteen models. The immutable preceding
candidate passes zero and fails fourteen; its nonzero report remains retained.

did not establish candidate compatibility.
